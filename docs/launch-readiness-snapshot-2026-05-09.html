  • Hero video re-encoding — only re-encode if iPhone Safari testing confirms autoplay still fails after the #9 fix. Don't preemptively re-encode.
  • Per-category hero images on /services — bare typography sections work for v1. Add admin upload UI for category images post-launch if Karlyne wants visual polish.

  • Custom Pabau lead form (replace iframe) — only if Pabau iframe perf turns out to be a sustained issue post-launch. Multi-day rebuild.
  • Mobile-Pabau deep link to native Pabau app — currently iframe-only. Native handoff is a P3 enhancement.
  • Booking conflict awareness — Pabau owns availability; we don't pre-validate.
  • Gallery / image lightbox on shop — single image per product is fine for launch.
  • Auth method beyond email/password — magic links, social OAuth, etc. Kept simple per Philip's earlier preference.

6 · Workflow Switch After Launch

The current "push to main" workflow is correct for now (no real users; live site = staging environment). The day Karlyne starts taking real bookings, the workflow needs to change:

  1. Local dev for changes — npm run dev, browser, iterate
  2. Push to a feature branch — Vercel auto-builds a preview URL
  3. Karlyne (or you) review on the preview URL
  4. Merge to main only after preview looks right — main = production
  5. Hot-fix process — for genuine emergencies, push to main directly is still allowed; document why in the commit message

The cutover signal: she shares the URL publicly OR runs ads OR books a paying client through the site.
